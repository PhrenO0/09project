# 개발 운영과 중단 복구

## 빠른 재개

1. `CHECKPOINT.md`, `git status --short`, 관련 파일만 읽는다.
2. `node scripts/snapshot.mjs`를 실행하고 `.work/latest.json`과 `.work/RESUME.md`를 확인한다.
3. 코드와 검증 결과를 체크포인트보다 우선한다. 재생 전 현재 diff를 확인한다.
4. 한 기능씩 구현하고 해당 검증을 실행한다. 작은 작업과 5분 이상 작업의 경계마다 디스크에 중간 결과를 저장한다.
5. 단계 전환, 오류, 종료 전에 사람이 `CHECKPOINT.md`에 결정과 진행 상황을 갱신한 뒤 스냅샷을 다시 만든다.

스냅샷은 로컬 파일만 읽고 `.work/`에 원자적으로 쓴다. Git을 변경하지 않고, 프로세스를 종료하지 않으며, 환경 변수나 비밀값을 읽거나 출력하지 않는다. `CHECKPOINT.md`는 사람이 쓴 판단 기록이므로 스크립트가 덮어쓰지 않는다. Git이 없거나 HEAD가 없는 경우에도 오류를 명시해 빈 상태를 clean으로 오인하지 않는다.

이 스냅샷은 **소스 코드 백업이 아니다**. 강제 종료 직전의 저장되지 않은 수정은 복구할 수 없다. 작은 파일 단위로 먼저 저장하고 검증된 마일스톤은 Git 커밋으로 남긴다. GitHub에 반영된 커밋이 있어야 장치 손실에도 대응할 수 있다. `.work/`는 로컬 경로와 진행 메모를 담으므로 원격에 올리지 않는다. 체크포인트·package scripts에도 비밀값을 쓰지 않는다.

이는 자동 스케줄러, 세션 부활, 또는 사용량 한도 우회 기능이 아니다. 앱이 이 프로젝트 설정을 현재 세션에서 즉시 다시 읽는지는 보장되지 않으며, 현재 도구 호출의 명시적 모델 오버라이드가 프로젝트 기본값보다 우선한다.

## 모델과 위임

- Astra: 불명확한 판단, 아키텍처, 콘텐츠 권리, 보안 검토와 최종 핵심 검토.
- Luna: 지정 사실 추출, 문서 정리, 반복 작업.
- Terra: 제한된 탐색, 간단한 구현 또는 검증.
- Sol: 명세가 정해진 여러 파일의 구현.

기본 동시 worker는 최대 2개다. 전체 대화 fork 없이 목표·소유 파일·인터페이스·완료 조건만 전달한다. 파일 소유권을 나누고 같은 파일을 동시에 수정하지 않는다.

capacity 오류는 적합한 다른 모델로 한 번만 대체할 수 있다. 계정 공통 usage-limit 오류가 나면 하위 모델을 계속 만들지 말고, 진행 상황을 저장하고 중단 사유를 기록한다. 토큰 절감률은 측정 검증 없이는 수치로 주장하지 않는다. 사용량은 계정 공통이며 실시간으로 변한다.

동일 실패는 새 증거 없이 두 번까지만 반복한다. 외부의 비멱등 작업(결제, 게시, 계정 생성 등)은 재시도 전에 결과를 조회한다. 검증은 변경한 동작에 맞는 구체적 명령으로 끝내며, 새 증거 없이 끝없이 실행하지 않는다.

## 사용량에 따른 작업 크기

아래는 모델 가격표나 하드 토큰 제한이 아니라 운영 기준이다. 사용량 도구로 확인 가능할 때, 5시간/주간 중 더 적게 남은 창을 기준으로 한다.

| 남은 사용량 | 운영 |
|---|---|
| 25% 초과 | 독립 작업 최대 2개, 한 작업 1개 흐름/명확한 완료조건 |
| 10~25% | 새 병렬 작업을 줄이고 현재 기능의 검증·정리 우선 |
| 10% 이하 | 새 큰 작업을 시작하지 않고 이미 한 변경의 정합성·체크포인트 확보 |
| usage-limit 오류 | 모델 연쇄 재시도 중단, 가능한 도구로 저장, 재개할 파일/명령 기록 |

사용량은 작업 시작·큰 단계 전환·한도 오류 때 확인한다. 매 도구 호출마다 조회하지 않는다. 정기 타이머나 계정 크레딧 자동 소비는 설정하지 않는다. 작업 중 새 사용자 지시가 오면 우선 반영한다.

## 토큰을 쓰는 곳과 줄이는 곳

- 권한·데이터 모델·계약 해석처럼 틀리면 재작업이 큰 판단은 Astra에 남긴다.
- 코드 탐색은 `rg`와 필요한 줄 범위, 문서는 제목/요약→필요 항목 순으로 읽는다.
- 조사 출처·버전·라이선스는 파일에 저장하고 새로 변할 수 있는 결정 직전에만 다시 확인한다.
- 검증은 타입/관련 회귀 테스트→UI 확인→릴리스 번들 순서. 변경 없는 전체 검증 재실행을 피한다.
- 외부 harness를 겹쳐 설치하지 않는다. 현재는 Codex + 짧은 프로젝트 스킬 + 체크포인트 + CI만 적용했다.
- 개선 효과는 작업별 재작업 횟수·실패 원인·읽은 범위와 확인 가능한 사용량으로 기록한다. 토큰 절감률을 추정해 성과로 보고하지 않는다.

## 프로젝트 에이전트 설정

`.codex/config.toml`은 주 모델 Astra, 기본 하위 모델 Luna/medium, 동시 하위 스레드 2개를 설정한다. `extract`, `worker`, `reviewer`는 각각 Luna, Sol, Astra 역할이다. 스키마는 OpenAI의 [Subagents 문서](https://learn.chatgpt.com/docs/agent-configuration/subagents)를 기준으로 했다. 이 문서는 `agents.default_subagent_model`, `agents.default_subagent_reasoning_effort`, `agents.max_concurrent_threads_per_session`과 프로젝트 `.codex/agents/*.toml`의 `name`, `description`, `developer_instructions`를 명시한다.
